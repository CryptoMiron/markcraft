# MarkCraft

[English](README.md) | Русский

MarkCraft — редактор Markdown, сделанный для Omarchy. Он открывает один файл в нативном окне Wayland (GTK3 + WebKitGTK), рисует GFM по мере набора и записывает файл обратно байт в байт. Ни хранилища заметок, ни базы данных, ни Electron, ни экрана настроек: палитра приходит из Omarchy, шрифт — из системы, а единственный источник истины — файл на диске.

> Проект разрабатывался в первую очередь для Omarchy и намеренно сделан в духе Omarchy: небольшое нативное приложение, системная тема и шрифты, никаких настроек внутри, никакого фонового демона и никаких ресурсов из сети.

- **Байтовая верность.** CRLF, BOM, табы, хвостовые пробелы, отсутствие финального перевода строки и юникод переживают цикл открытия и сохранения. Тесты открывают каждый файл из `fixtures/` и сравнивают байты; ручная проверка перед релизом сохраняет каждую фикстуру без правок и сверяет через `cmp`.
- **Текст, а не AST.** Правка меняет сам исходный Markdown; сериализатора AST → Markdown, который переформатировал бы файл, нет.
- **Интеграция с Omarchy.** Читает текущую палитру из `$XDG_STATE_HOME/omarchy/current/theme/colors.toml` (обычно `~/.local/state/…`), перекрашивается на лету после `omarchy theme set`, красит нативные GTK-диалоги, следует системному масштабу текста; в комплекте `.desktop`, иконка и PKGBUILD для Arch.
- **Живой предпросмотр GFM на CodeMirror 6.** Метрики Inkdown: база 16 px, колонка 700 px, системные sans и mono. Маркеры видны только в редактируемой строке. В блоках кода — 13 языков, номера строк и кнопка копирования; YAML-шапка показывается блоком кода.
- **Правки переживают сбой.** Автосейв идёт по таймеру 1,2 с для файла с путём (восстановленный черновик ждёт явного Ctrl+S); черновик пишется по таймеру 300 мс и переживает `kill -9`. Внешние изменения отслеживаются опросом `mtime` и размера раз в 700 мс: можно перечитать файл или оставить свою версию. Запись идёт через временный файл и `rename`, права сохраняются; файл только для чтения не перезаписывается.
- **Один процесс — много окон.** Ctrl+N открывает новое окно в том же процессе; повторное открытие уже открытого файла поднимает его окно. Относительные ссылки на `.md`, `.markdown` и `.txt` открываются в MarkCraft, внешние адреса — в системном браузере.
- **Один бинарник без ресурсов из сети.** CSS и JS вкомпилированы в исполняемый файл, GTK3 и WebKitGTK берутся из системы. Ни CDN, ни телеметрии, ни проверок обновлений.
- **13 языков подсветки:** Rust, Python, JavaScript/TypeScript, JSON, Shell, YAML, TOML, SQL, Go, C, C++, CSS, XML/HTML.
- **Интерфейс на en/ru** из `LANGUAGE` / `LC_ALL` / `LC_MESSAGES` / `LANG`; язык читается один раз при запуске, всё, кроме русского, — английский.
- **Строка состояния и копирование HTML.** Путь сокращается до `~`, рядом счётчики слов, символов и строк; Ctrl+Shift+C кладёт в буфер HTML и Markdown как plain text.

## Пример

```sh
markcraft                  # пустое окно
markcraft notes.md         # открыть файл
markcraft --help           # справка
markcraft --version        # версия
```

Документ, который MarkCraft показывает без сюрпризов:

```md
# Релиз 0.1

- [x] Байтовая верность
- [ ] Таблицы с выравниванием

| Клавиша | Действие |
| ------- | -------- |
| `Ctrl+S` | Сохранить |
```

MarkCraft рисует это на лету, а маркеры Markdown видны только в строке, которую вы правите. Нажмите Ctrl+S — и на диске будет ровно то, что вы набрали.

## Установка

MarkCraft работает на Linux и требует GTK3, WebKitGTK 4.1 и `xdg-desktop-portal`. На Omarchy или Arch есть два способа установки.

### Пакет из релиза

Скачайте пакет и `SHA256SUMS` со [страницы релизов](https://github.com/CryptoMiron/markcraft/releases), проверьте сумму и установите:

```sh
curl -fLO https://github.com/CryptoMiron/markcraft/releases/download/v0.1.0/markcraft-0.1.0-1-x86_64.pkg.tar.zst
curl -fLO https://github.com/CryptoMiron/markcraft/releases/download/v0.1.0/SHA256SUMS
sha256sum -c SHA256SUMS
sudo pacman -U markcraft-0.1.0-1-x86_64.pkg.tar.zst
```

В пакете бинарник, `.desktop`, иконка и лицензия. Пакет не подписан, поэтому целостность проверяется суммой. Файл в релизе собран для `x86_64`; на `aarch64` используйте установку из исходников.

### Одна команда из исходников

Соберёт последний `master` и поставит его пакетом:

```sh
curl -fsSL https://raw.githubusercontent.com/CryptoMiron/markcraft/master/bin/install | bash
```

Скрипт спросит пароль sudo, доставит недостающие инструменты сборки, соберёт пакет Arch из последнего `master` и установит его через `pacman`. После этого `pacman -Q markcraft` находит пакет, ярлык и иконка появляются в системе, а `sudo pacman -R markcraft` удаляет всё. Повторный запуск той же команды обновляет MarkCraft.

Пакет собирается из исходников: для первой установки нужны сеть и несколько минут. Rust, Bun и Python придут как зависимости сборки, а GTK3, WebKitGTK 4.1 и `xdg-desktop-portal` — как зависимости пакета. Скрипт лежит в [`bin/install`](bin/install): прочитайте его перед запуском через `| bash`.

### Запуск из чекаута

Чтобы запустить чекаут без установки:

```sh
sudo pacman -S --needed base-devel rust gtk3 webkit2gtk-4.1 xdg-desktop-portal
git clone https://github.com/CryptoMiron/markcraft.git
cd markcraft
cargo build --release --locked
./target/release/markcraft README.md
```

`ui/built.html` лежит в репозитории, поэтому для этой сборки Bun не нужен.

Если меняете интерфейс, поставьте инструменты сборки и пересоберите страницу:

```sh
sudo pacman -S --needed bun python3
bun install --frozen-lockfile
bin/bundle
cargo build --release --locked
```

После правки `ui/*.js` или `ui/*.css` обязательно запускайте `bin/bundle`: `bin/check` падает, если `ui/built.html` разошёлся с исходниками.

Полная проверка:

```sh
./bin/check
```

Сборка и установка пакета из чекаута без скрипта:

```sh
cd pkgbuild
makepkg -fsi
```

`makepkg` пересобирает встроенный интерфейс через `bin/bundle` (Bun + Python 3) и устанавливает бинарник, `.desktop` и иконку в hicolor.

## Сделано для Omarchy

MarkCraft разрабатывался в первую очередь как приложение для Omarchy. У него нет своего движка тем и экрана настроек: он берёт то, что уже дают Omarchy и рабочий стол, и не мешает остальному.

| Что | Откуда берётся |
| --- | --- |
| Палитра | `$XDG_STATE_HOME/omarchy/current/theme/colors.toml` (обычно `~/.local/state/omarchy/current/theme/colors.toml`) |
| Светлая или тёмная | `mode` из того же файла; если ключа нет — яркость `background` |
| Размер текста | `org.gnome.desktop.interface text-scaling-factor` через портал XDG, с ограничением 0,5–3,0 |
| Смена темы на лету | `gio::FileMonitor` на `omarchy/current` и `omarchy/current/theme` |
| Диалоги | GTK CSS-провайдер с той же палитрой, чтобы нативные диалоги не выглядели как чужой Adwaita |
| Запуск | `.desktop` с `MimeType=text/markdown;text/x-markdown;text/plain`, иконка hicolor |
| Тайлинг | работает в Hyprland, ужимается до 280×200 без горизонтальной прокрутки |

Проверить на живом окне:

```sh
omarchy theme set tokyo-night
omarchy theme set catppuccin-latte
```

Открытое окно перекрашивается без перезапуска. Полноэкранный режим остаётся за Omarchy (`Meta+F`), MarkCraft его не перехватывает.

## Клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl+O` / `Ctrl+S` / `Ctrl+Shift+S` | Открыть / сохранить / сохранить как |
| `Ctrl+N` | Новое окно в том же процессе |
| `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` | Отменить / вернуть |
| `Ctrl+B` / `Ctrl+I` / `Ctrl+Shift+X` | Жирный / курсив / зачёркнутый |
| `Ctrl+K` | Ссылка; внутри готовой ссылки выделяет адрес |
| `Ctrl+F` / `Ctrl+H` | Поиск / поиск с заменой |
| `Enter` / `Ctrl+G` / `Shift+Enter` / `Esc` | Дальше / дальше / назад / закрыть поиск |
| `Ctrl+=` / `Ctrl+-` / `Ctrl+0` / `Ctrl+колесо` | Размер текста |
| `Ctrl+Shift+C` | Скопировать документ как HTML и Markdown как plain text |
| `Ctrl+?` / `Ctrl+/` / `F1` | Справка по клавишам |
| `Ctrl+клик` по ссылке | Относительный файл — в MarkCraft, `#якорь` — в текущем документе, внешний адрес — в браузере |
| `Enter` в списке | Продолжить список, задачу или цитату; пустой пункт выходит из списка |
| `Tab` / `Shift+Tab` | Увеличить / уменьшить вложенность пункта |

## Архитектура

MarkCraft — приложение на Rust с GTK3 и WebView на WebKitGTK. Rust отвечает за файл, состояние на диске и интеграцию с системой; WebView — за правку, рендер и строку состояния.

```text
GApplication (один процесс, много окон)
└── ApplicationWindow
    └── WebKitGTK WebView
        └── CodeMirror 6: правка, живой предпросмотр, поиск

Rust:
├── Doc: байты, автосейв, черновик, конфликты с диском
├── Theme: colors.toml, GTK CSS, мониторы темы
└── i18n: en/ru, диалоги, буфер обмена, ссылки
```

| Путь | За что отвечает |
| --- | --- |
| `src/main.rs` | GApplication, окна, IPC, автосейв, таймеры черновика, слежение за диском, диалоги, буфер обмена, ссылки |
| `src/doc.rs` | Байтовый `Doc`, CRLF/BOM, атомарная запись, черновик, размер окна |
| `src/theme.rs` | Разбор `colors.toml` от Omarchy, CSS-переменные, CSS для GTK-диалогов, масштаб из портала, мониторы темы |
| `src/i18n.rs`, `src/locales/` | Выбор языка и словари en/ru |
| `ui/editor.js` | Редактор на CodeMirror 6, декорации живого предпросмотра, поиск, маршрутизация клавиш, мост `window.mc` |
| `ui/*.test.js` | Тесты Bun для чистых правил интерфейса: клавиши, правка, ссылки, шапка файла, блоки кода, история, поиск |
| `ui/built.html` | Одна страница интерфейса, вкомпилированная в бинарник; лежит в репозитории, чтобы `cargo build` работал без Bun |
| `fixtures/` | Корпус для байтового round-trip: CRLF, BOM, табы, отсутствие финального перевода строки, шапка, GFM, языки кода |
| `docs/` | Требования, типографика, процесс, отказы и журнал решений |
| `pkgbuild/` | Пакет Arch, `.desktop` и иконка |

**Поток данных**

- **Загрузка:** байты → проверка UTF-8 → запоминание EOL и BOM → текст с LF в памяти → `window.mc.loaded` (без записи в историю отмены).
- **Правка:** CodeMirror отправляет `dirty` с полным текстом; Rust обновляет `Doc` и планирует черновик (300 мс) и автосейв (1,2 с).
- **Сохранение:** байты собираются с исходными EOL и BOM, пишутся в `.markcraft-tmp`, права копируются, затем временный файл переименовывается поверх целевого.
- **Внешнее изменение:** отпечаток `mtime` и размера опрашивается раз в 700 мс. Без своих правок файл перечитывается молча; со своими — диалог «перечитать / оставить моё»; удаление — «сохранить заново / оставить как есть».
- **Тема:** небольшой встроенный парсер `colors.toml` без зависимости от TOML выдаёт одно правило `:root{…}`; CSS для GTK-диалогов обновляется синхронно.

**Сборка интерфейса**

```text
ui/template.html + ui/style.css + ui/*.js
        │ bun build (bin/bundle)
        ▼
ui/editor.bundle.js  →  ui/built.html (лежит в репозитории)
        │ include_str!
        ▼
Бинарник Rust
```

Rust вставляет выбранный словарь en/ru в страницу до запуска бандла редактора. Нет async runtime и фонового сервиса: все окна живут в одном процессе GApplication и одном цикле GTK.

Хост написан напрямую на `gtk-rs` + `webkit2gtk-rs`: на момент выбора бэкенд wry под Linux умел только X11, а MarkCraft — нативное приложение Wayland. Решение записано в [`docs/CUTS.md`](docs/CUTS.md).

## Переменные окружения и состояние

| Переменная | Зачем нужна |
| --- | --- |
| `XDG_STATE_HOME` | База для состояния MarkCraft и пути к теме Omarchy. По умолчанию `$HOME/.local/state`. |
| `HOME` | Запасной вариант, если `XDG_STATE_HOME` не задан; ещё используется, чтобы сокращать путь до `~` в статусбаре. |
| `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG` | Язык интерфейса, проверяются в этом порядке. `ru` включает русский, всё остальное — английский. Читается один раз при запуске. |
| `MC_DEBUG` | Если задана, печатает сгенерированный CSS темы в stderr. |

Файлы состояния в `$XDG_STATE_HOME/markcraft/`:

| Файл | Содержимое |
| --- | --- |
| `draft` | Общий аварийный черновик (JSON `{path, text}`); восстанавливается при следующем запуске |
| `zoom` | Множитель масштаба текста |
| `window` | Последние ширина и высота окна; позицию назначает композитор Wayland |

Примеры:

```sh
XDG_STATE_HOME=/tmp/mc-state ./target/release/markcraft README.md
LANGUAGE=ru ./target/release/markcraft README.md
```

## Тесты

```sh
./bin/check
```

Скрипт запускает:

- `cargo fmt --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test` — сейчас 29 тестов Rust: байтовый round-trip по `fixtures/`, сохранение, CRLF/BOM, черновик, состояние диска, разбор темы и ограничение масштаба, CSS темы, разбор ссылок, i18n
- `bun test ui/` — сейчас 71 тест интерфейса: горячие клавиши по физической клавише, правила правки, разбор ссылок, шапка файла, границы блоков кода, поиск и `replaceAll`, история
- `bin/bundle`, затем падает, если `ui/built.html` изменился

Рендер проверяется глазами, а не эталонным HTML: тест на эталонный HTML пришлось бы обновлять после каждого рефакторинга, а от смены шрифта он падал бы. Ручной чек-лист лежит в [`docs/PROCESS.md`](docs/PROCESS.md).

Перед закрытием релиза откройте каждую фикстуру и сохраните её без правок: `cmp` должен быть чистым.

## Ограничения

- Нет хранилища заметок, базы, тегов и wiki-ссылок. Одно окно — один документ; вкладок, сайдбара и сплит-панелей нет.
- Нет KaTeX, Mermaid, экспорта в PDF, DOCX и HTML, плагинов, синхронизации, git-интеграции, чата и LLM.
- Живой предпросмотр — слой декораций поверх Markdown, а не блочный WYSIWYG: нет drag-handle и slash-меню.
- WebKitGTK занимает примерно 100 МБ RSS. Это цена полноценного движка вёрстки без Electron.
- Масштаб текста применяется при запуске и при смене темы; сигнал портала не слушается на лету.
- Полноэкранный режим остаётся за Omarchy.
- При `kill -9` может потеряться до 300 мс последнего набора. Черновик общий для всех окон: один файл `draft`, а не по файлу на окно.
