# Чего MarkCraft не делает

Список существует, чтобы отказ был решением, а не забывчивостью. Строка отсюда
переезжает в SPEC только если пользователь явно попросил — и тогда с датой.

## Не делаем в v1

| Что | Почему |
|---|---|
| База заметок, дерево, теги, wiki-ссылки | Это Inkdown. MarkCraft — редактор файлов; файл и есть заметка |
| Чат, LLM, вложения, промпты | Другая профессия приложения |
| KaTeX и math | Отдельная тема, отдельный вес; omalorem показывает, как это раздувает проект |
| Mermaid, диаграммы | То же |
| Экспорт PDF / docx / HTML-файла | Ctrl+P печатает через системный диалог, этого хватает |
| Вкладки, сайдбар, сплит-панели | Одно окно — один документ, как в omawrite |
| Настройки в UI | Тема из Omarchy, шрифт из системы, размер — Ctrl+= |
| Плагины, темы-пакеты, сниппеты | Нечего расширять, пока нет ядра |
| Синхронизация, git, облако | Файл лежит на диске; синхронизирует тот, кто за это платит |
| Мобильная/веб-версия | Один бинарник под Linux |
| WYSIWYG с drag-handle блоков и slash-меню | Дорого и ломает байтовую верность; живём на live-preview |
| Своя палитра, свой шрифт | I5 в SPEC |
| Markdown-рендер на QTextDocument | Проверено: теряет данные (см. ниже) |

## Известные потолки (не «потом», а «так и задумано»)

- **WebKitGTK, а не Chromium.** Рендер на несколько процентов отличается от Inkdown по растеризации. Приемлемо: совпадают метрики и шрифт, а не пиксели.
- **~100 МБ RSS.** Меньше Electron, больше egui. Цена за готовый движок вёрстки.
- **Нет «красивых» таблиц-виджетов с ресайзом колонок.** Таблица — отрендеренный markdown, правится как текст.

## Записанные факты, чтобы не перепроверять

- `QTextDocument::MarkdownDialectGitHub` в Qt 6.12 при round-trip теряет: курсив в заголовке, setext-разметку, выравнивание колонок таблицы, hard break, разделение сносок и сырого HTML. Поэтому QML `TextEdit.MarkdownText` и любой путь через `QTextDocument` запрещены инвариантом I2.
- Inkdown — AGPL-3.0, код не копируется. Из него берутся только числа из `docs/TYPOGRAPHY.md`, которые являются фактами о вёрстке, а не кодом.
- **wry на Linux умеет только X11.** `wry 0.57.1 → webkitgtk/mod.rs::new_x11` принимает только `RawWindowHandle::Xlib`, фича `x11` включена по умолчанию, Wayland-рукла нет вовсе. Попытка `WebViewBuilder::new().build(&tao_window)` на Wayland падает с `Error::UnsupportedWindowHandle`. Следствие: оболочка — прямо на `gtk-rs` + `webkit2gtk-rs`, без wry/tao. Это меньше кода, а не больше, и Wayland нативный (`hyprctl clients` показывает `xwayland: false`).
