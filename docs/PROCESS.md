# Как ведётся разработка

Проблема не в том, чтобы «ничего не забыть» — забыть можно что угодно. Проблема в том,
чтобы **забытое падало само**. Поэтому процесс состоит из четырёх механизмов, и ни один
из них не держится на памяти.

## 1. Спека — единственный источник правды

`docs/SPEC.md`, требования `R1.1 … R5.6`. Правила:

- Новая идея сначала становится строкой в SPEC, потом кодом. Не наоборот.
- Строка без галочки — не сделано, даже если «вроде работает».
- Строка с галочкой имеет рядом дату и то, чем проверена.
- Появилось желание сделать что-то, чего в SPEC нет, — это `docs/CUTS.md`, а не код.

Спека пишется **до** среза и не переписывается задним числом под то, что получилось.

## 2. Порядок срезов: сначала скелет целиком, потом мясо

Не так: месяц рендера, потом обнаруживается, что сохранение портит файл.
А так — S1 первым, потому что это самый рискованный стык (файл ↔ буфер ↔ диск).

| Срез | Выход | Что ловит |
|---|---|---|
| **S0. Каркас** | окно открывается, `cargo run` живёт | среда, Wayland, wry |
| **S1. Файлы** | открыл → сохранил → `cmp` чист | порча данных, портал, автосейв |
| **S2. Рендер** | фикстура выглядит как Inkdown | типографика, GFM-покрытие |
| **S3. Правка** | правка одной строки = diff одной строки | IME, undo, маркеры |
| **S4. Omarchy** | смена темы живьём | интеграция с системой |
| **S5. Клавиши** | чек-лист R5 пройден | мелкие обещания |

Срез не начинается, пока предыдущий не закрыт по своему выходу. Внутри среза — можно
и нужно резать на коммиты, но не на «полуготово».

## 3. Тесты только на то, что дорого стоит

Не покрываем всё. Пишем тест там, где ошибка = потеря данных или тихая ложь:

1. **`save_roundtrip`** — открыть каждый файл из `fixtures/`, сохранить без правок, `assert_eq!` байтов. CRLF, BOM, табы, без финального `\n`, кириллица, эмодзи. Это первый тест проекта и он не удаляется никогда.
2. **`edit_one_line`** — правка одной строки меняет только её (диф).
3. **`theme_parse`** — `colors.toml` без ключа, с мусором, с битым hex → не паникует, берёт дефолт.
4. **`scale_clamp`** — 0.1 и 5.0 из портала не ломают вёрстку.

Рендер тестами не покрывается — он проверяется глазами по скриншоту. Тест «HTML совпал
с эталоном» здесь врёт: он зеленеет при рефакторинге и краснеет при смене шрифта.

## 4. Ручной прогон перед закрытием среза

Один раз на срез, по строкам SPEC, руками, в реальном окне. Не «я помню, что работало».
Результат — галочки и, если что-то всплыло, новая строка R в SPEC или строка в CUTS.

Модальные GTK-диалоги через `wtype` не нажимаются: виртуальная клавиатура до них не
доходит, хотя окно активно. Их проверяем мышью, а в SPEC пишем «визуально проверено».
Так уже отмечен R1.4.

Отдельно на каждом срезе — три вещи, которые не проверяются автоматически:

- **IME:** переключиться на русскую раскладку, набрать абзац, стереть, отменить.
- **Мышь:** клик в середину жирного слова, выделение через границу блока, скролл колесом.
- **Файл:** открыть в другом редакторе после сохранения и убедиться, что разметка цела.

## 5. Долги не копятся молча

Любой сознательный компромисс получает в коде комментарий:

```
// shortcut: <что именно не так>, <когда чинить>
```

`grep -rn "shortcut:" src/` — это и есть список долгов. Он либо пуст, либо объяснён.

## Риски, за которыми следим

| Риск | Когда проверяем | Что делаем, если сработал |
|---|---|---|
| IME ломается декорациями CM6 | S3, первый же день | отключаем декорации вокруг composition-региона, оставляем только стили |
| WebKitGTK джанкует на длинном документе | конец S2, файл на 5k строк | виртуализация через `viewRange`, иначе — смена оболочки (см. CUTS) |
| Расхождение рендера с Inkdown | S2, сравнение скриншотов | правим CSS, а не «примерно похоже» |
| wry на Wayland с фракционным масштабом | S0 | `GDK_SCALE`/`GDK_DPI_SCALE`, флаг окна |

## Что это стоит

- SPEC + CUTS + TYPOGRAPHY: полдня один раз, дальше 5 минут на фичу.
- Тесты из п.3: ~150 строк на весь проект.
- Ручной прогон: 20 минут на срез.

Дешевле, чем один потерянный документ пользователя.
