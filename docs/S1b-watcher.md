# S1b — Внешние изменения

Выход среза: если файл изменили вне MarkCraft, об этом сообщают, автосейв
останавливается, пользователь выбирает «перечитать» или «оставить моё».

**Готово 2026-10-25.**

## Как сделано

Не inotify, а опрос раз в 700 мс: сравниваем `mtime` + размер файла с отпечатком,
снятым при последнем чтении или записи (`Doc::stamp`). Причины:

- не нужны права на каталог и `notify` в зависимостях;
- на атомарной записи через `rename` inotify всё равно даёт `MOVED_TO`, который
  пришлось бы отдельно разбирать;
- 700 мс незаметны человеку, а лишние 1–2 `stat` в секунду бесплатны.

Отпечаток обновляется и при нашей записи, поэтому свой автосейв не выглядит
чужим изменением.

## Поведение

| Ситуация | Что происходит |
|---|---|
| Файл изменён, своих правок нет | Молча подхватываем версию с диска, черновик убираем |
| Файл изменён, есть свои правки | Диалог: «Перечитать» (потерять моё) / «Оставить моё» (записать поверх) |
| «Оставить моё» | Отпечаток принимается, автосейв взводится заново и пишет поверх |
| Файл удалён | Диалог: «Сохранить заново» / «Оставить как есть» |
| «Оставить как есть» | Файл не пересоздаётся, автосейв на паузе, второй раз не спрашиваем, текст живёт в черновике |
| Файл вернулся | Флаг «уже спрашивали» сбрасывается |

Почему без своих правок не спрашиваем: «оставить моё» оставило бы в буфере
устаревший текст, и следующий автосейв затёр бы им чужую версию. Молчаливое
подхватывание здесь безопаснее любого вопроса.

## Проверка

```sh
./target/release/markcraft /tmp/a.md &
echo "правка снаружи" >> /tmp/a.md          # без правок в окне → подхватилось
# с правками → диалог; «Оставить моё» → файл содержит и чужое, и моё
rm /tmp/a.md                                # → «Сохранить заново / Оставить как есть»
```

Прогнано руками 2026-10-25 через `wtype` + `hyprctl dispatch hl.dsp.send_shortcut`
(модальные GTK-диалоги принимают клавиши только через композитор, не через `wtype`).
